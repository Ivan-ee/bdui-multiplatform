# Map: BDUI Rental PoC (`wayfinder:map`)

> **АРХИВ.** Канонический трекер перенесён в GitHub Issues: [Карта #9](https://github.com/Ivan-ee/bdui-multiplatform/issues/9). Этот файл больше не обновляется, см. [MIGRATED.md](MIGRATED.md).

## Destination

Работающий PoC сервиса аренды недвижимости: Go-бэкенд + три клиента (Android, iOS, веб-кабинет) из одной кодовой базы Kotlin Multiplatform, где весь UI описывается через BDUI (DivKit). Успех = сквозной сценарий «каталог → карточка объекта → оплата (заглушка) → личный кабинет» работает на всех трёх клиентах, плюс записанные выводы «берём / не берём» по каждому слою для настоящего сервиса пользователя.

## Notes

- Бэкенд пользователя сейчас и в проде — **Go**, поэтому бэкенд PoC пишем на Go и исследуем связку Go ↔ KMP-клиенты.
- Публичный лендинг сайта у пользователя уже есть отдельно; в PoC делаем только веб-приложение (личный кабинет), SEO не нужно — это развязывает руки BDUI на вебе.
- В PoC входят модули: каталог + карточка объекта, личный кабинет двух ролей (Арендатор / Арендодатель), оплата-заглушка. Полноценные заявки/бронирования НЕ включены — сценарий оплаты должен аккуратно связать каталог и кабинет (см. тикет модели данных).
- Цель теста: полный цикл на трёх клиентах из одной кодовой базы — где грабли.
- Десктоп снят со скоупа (27.08.2026, решение пользователя): у DivKit нет desktop-рендерера, усложнять PoC не хотим. Shared-модуль собирается только под Android/iOS/js; jvm-таргет не нужен.
- Сессиям тикетов консультироваться со скиллами `research`, `grilling`, `domain-modeling`.
- Язык проекта: русский. Термины — в `/CONTEXT.md`.

## Decisions so far

- [Зрелость Kotlin Multiplatform и Compose Multiplatform](issues/01-kmp-zrelost.md): ядро KMP стабильно (Kotlin 2.4.10, июль 2026); UI-слой мобильных берём нативным (Jetpack Compose + SwiftUI) поверх shared commonMain — паттерн индустрии «shared logic, native UI», а CMP не нужен, потому что экраны описывает BDUI.
- [Выбор BDUI-движка: DivKit и альтернативы](issues/02-bdui-dvizhok.md): остаёмся на DivKit 33.x (Apache-2.0, живые еженедельные релизы) — единственный активно развиваемый кроссплатформенный OSS SDUI-движок; Android (View+Compose клиент), iOS (Swift SPM SDK), Web (vanilla JS c SSR) поддержаны полноценно; **desktop/JVM-таргета нет**; все OSS-альтернативы мертвы.
- [Лучшие практики Go-бэкенда крупных компаний](issues/03-go-backend-praktiki.md): stdlib net/http (Go 1.22+ ServeMux), структура cmd/server + internal/{transport,service,storage}, PostgreSQL 17 + pgx/v5 + sqlc, миграции goose, golang-jwt/v5 (access+ротация refresh, argon2id), OpenAPI spec-first → oapi-codegen, slog, ошибки RFC 9457 problem+json.
- [Интеграция Go-бэкенда с KMP-клиентами](issues/04-integraciya-go-kmp.md): OpenAPI 3 спека Go = единственный контракт; только модели генерируются openapi-generator (`@Serializable`, models-only), endpoint-слой вручную поверх Ktorfit 2.7.5 + Ktor Client 3.5; движки expect/actual OkHttp/Darwin/CIO(+Js); DI Koin в commonMain; JSON kotlinx.serialization; токены через multiplatform-settings.
- [Стратегия BDUI на десктопе](issues/05-desktop-strategiya.md): Windows/macOS = **Tauri-окно вокруг того же DivKit web-кабинета** (1–3 дня работы, общий js-target shared-модуля нужен вебу так и иначе); план Б для продуктового этапа — JCEF WebView внутри Compose Desktop (kmpJsBridge); ограничение вывода PoC: нативность и OS-глубина десктопа тестом не проверяются.
- [Подтверждение итогового стека](issues/06-podtverzhdenie-steka.md): стек подтверждён пользователем целиком; по десктопу пользователь выбрал вариант «WebView внутри Compose Desktop» вместо рекомендованного Tauri — честное JVM-приложение, риски приняты, Tauri остаётся планом Б. Следующий шаг — модель данных (07), затем вертикальный срез (08).

## Not yet specified

- Авторизация: схема токенов уже выбрана ресерчем (JWT access 10–15 мин + ротация refresh в БД, argon2id); остались сценарии регистрации/ролей и политика хранения на вебе (HttpOnly cookie + короткий access в памяти) — уточнить при тикете модели данных или срезе.
- Как версионировать и обновлять BDUI-layout'ы: breaking changes схемы DivKit 33.0.0 показали нужду версионирования layout'ов на бэкенде + фиксации SDK-версий клиентов.
- Веб-кабинет технически: js-таргет shared-модуля (wasmJs пока Beta — хватит js), сборка Vite vs bare; станет острым на вертикальном срезе.
- Дизайн-система: кастомные компоненты поверх DivKit, шрифты, иконки, тёмная тема — острота вопроса станет ясна после прототипа.
- CI и сборка под все платформы: собрать все source sets (android, ios, js) в CI с первого дня (митигация wasmJs/Ktorfit рисков), полный пайплайн осмысленно после вертикального среза.
- Хостинг демо-окружения: локальный docker-compose против облака — зависит от того, покажет ли PoC необходимость общего доступа.
- Тестирование shared-логики и API-контрактов между Go и KMP (контрактные тесты, регенерация DTO по диффу спеки в CI).

## Out of scope

- Десктопные приложения Windows/macOS — сняты со скоупа 27.08.2026 решением пользователя: у DivKit нет desktop-рендерера, усложнять PoC не хотели (исследование вариантов и рекомендация Tauri/WebView остались в закрытом тикете [Стратегия BDUI на десктопе](issues/05-desktop-strategiya.md)).
- Публичный лендинг/витрина сайта — у пользователя уже есть отдельный лендинг; здесь только приложение-кабинет.
- Реальный платёжный процессинг — договорились на заглушку.
- Публикация приложений в сторы, автосборки релизов — проверяется мануально локально.
- Высокие нагрузки, масштабирование, мониторинг продакшн-уровня.
