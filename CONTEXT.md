# Arenda Platform PoC

Тестовое приложение для проверки стека будущего сервиса управления арендой недвижимости: Go-бэкенд + три клиента (Android, iOS, веб-кабинет) на Kotlin Multiplatform с единым сервер-драйвен UI.

## Language

### Подход и технологии

**BDUI**:
Backend-Driven UI — подход, при котором структура экрана приходит с сервера как данные, а клиенты только отрисовывают её нативными средствами.
_Avoid_: DBUI, server-driven UI (как разговорный синоним)

**DivKit**:
Опенсорсный движок BDUI от Яндекса — кандидат на роль единственного способа описывать UI во всех клиентах PoC.

### Роли

**Арендодатель**:
Пользователь, размещающий свои объекты недвижимости в аренду и обрабатывающий входящие заявки.
_Avoid_: хост, owner

**Арендатор**:
Пользователь, ищущий объект и оплачивающий аренду.
_Avoid_: клиент, гость

### Домен

**Объект**:
Помещение (квартира, комната, дом), которое арендодатель сдаёт в аренду; единица каталога.
_Avoid_: листинг, объявление, property

**Оплата-заглушка**:
Имитация платежа без реального процессинга: фиксирует факт «оплаты» аренды объекта для сквозного сценария PoC.

**Платёж**:
Результат успешной Оплаты-заглушки: привязывает Арендатора к Объекту и его Окну аренды с фиксированной суммой; всегда со статусом «успешно».
_Avoid_: транзакция, счёт

**Окно аренды**:
Период аренды Объекта, который Арендатор выбирает при оплате: дата начала плюс длительность из фиксированных вариантов (1, 3, 6 или 12 месяцев). В PoC заявок и бронирований нет — окно живёт только внутри Платежа.
_Avoid_: бронирование, booking

**Занято**:
Статус Объекта после первой успешной оплаты: занятый Объект скрыт из каталога, но виден Арендодателю в его кабинете.
_Avoid_: забронирован, недоступен
